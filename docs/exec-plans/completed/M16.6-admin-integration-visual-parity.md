Status: completed
Milestone: M16.6
Depends on: M16.1 Dashboard, M16.2 Customers, M16.3 Segments, M16.4 Promos, M16.5 Communications, M16.5.1 Communications Persistence

## Purpose

Провести финальный Admin integration/hardening slice после реализации отдельных M16 domains.

M16.6 не добавляет новую business domain logic. Он собирает и проверяет единый Admin experience:

- sidebar и mobile navigation;
- Dashboard;
- Orders;
- Catalog/Menu;
- Loyalty;
- Promos;
- Quests;
- Wheel;
- Customers;
- Segments;
- Communications;
- auth/logout/session recovery;
- common loading/error/empty/unavailable states;
- responsive и visual parity с prototype.

## Scope

### Admin shell/navigation

- Verify all available sections are reachable from the sidebar.
- Verify active navigation state and mobile page title.
- Verify sidebar drawer open/close, backdrop, Escape and click-away behavior.
- Verify logout and session expiration from every section.
- Verify direct refresh preserves safe authenticated/unavailable state.
- Verify disabled/unavailable controls are clearly labelled.
- Verify no nav item points to a missing or fake page.

### Cross-section integration

- Segments → Communications opens the correct segment context.
- Promotions definitions display their truthful availability and do not mutate checkout unexpectedly.
- Customers data remains masked and consistent with Orders/Loyalty.
- Dashboard aggregates match underlying confirmed records.
- Communications drafts retain segment/promo/template versions.
- Existing Wheel/Quest/Loyalty definitions remain accessible and protected.

### Shared states and UX

- Standardize loading, retry, empty, no-match, unavailable and reconciliation presentation.
- Standardize safe error copy and avoid raw Backend errors.
- Standardize pagination/filter controls.
- Preserve accessible labels, roles, focus and keyboard behavior.
- Keep console free of unhandled errors and warnings caused by M16 integration.

### Responsive/visual hardening

- Capture every Admin section at `320`, `375`, `768`, `1024`.
- Compare with corresponding prototype page and established current production shell.
- Fix horizontal overflow, clipped rows, modal overflow, hidden controls and broken mobile topbar.
- Check chart/table readability and touch targets.
- Use one bounded visual pass and one confirmation pass; avoid open-ended polishing.

## Out of Scope

- new promo economics;
- new segment criteria;
- new communications persistence semantics;
- Customer loyalty redemption;
- delivery workflow;
- production native store submission;
- new database/cache/queue infrastructure.

## Discoveries

- Current Admin shell already includes Dashboard, Promos, Customers, Segments and Communications routes.
- M16.6 is primarily integration/visual hardening, not a new data-domain implementation.
- Existing Admin login limiter must be respected by E2E grouping or fixed in the test harness without weakening security.
- Added `admin-integration.spec.ts`; the integrated walkthrough passed all 10 Admin sections and responsive overflow checks at `320`, `375`, `768`, `1024`.
- At `1024px`, the collapsed sidebar hid nav text from the accessibility tree; explicit button labels/titles and authored SVG icons now keep all 10 routes discoverable.
- Mobile screenshot capture must wait for the existing 300ms drawer transition; the production drawer closes immediately by state and the capture harness now records the settled layout.
- The workspace package name is `@vse-pro-zhar/database`; the legacy `@vse-pro-zhar-database` filter in older plan commands matches no project.

## Decision Log

- M16.6 does not add Push/SMS or new provider integrations.
- Prototype visual composition remains mandatory for all matching Admin surfaces.
- Existing section-specific business rules remain authoritative; M16.6 only connects and verifies them.
- The first integration run exposed a test-only mobile drawer click issue; the test now opens the mobile sidebar before selecting a section, with no production code change required.
- Shared modal behavior is implemented once for Catalog, Promos, Segments and Communications: focus return/trapping, Escape, click-away and body scroll lock; this changes interaction safety without changing domain behavior.
- E2E is executed directly with `pnpm exec playwright test --workers=1` because the root `pnpm e2e -- --workers=1` wrapper passes the extra separator through and does not enforce the requested worker count.
