# M15.1 — Phone-only Customer authentication

Status: completed
Milestone: M15
Depends on: M5 Customer authentication, M15 native Push registration

## Purpose

Убрать SMS-код из Customer login. Web, iOS и Android используют простой server-backed вход по номеру телефона; Push остаётся отдельной native-функцией.

## Current State

M15 добавил SMS OTP UI/API, но owner уточнил, что кодовые сообщения не нужны: пользователь вводит только номер телефона и продолжает работу.

## Scope

- Сделать имя и дату рождения необязательными в auth contract; минимальный ввод — телефон.
- Использовать один phone-only auth modal на Web/iOS/Android.
- Убрать SMS OTP request/verify из runtime auth flow и не вызывать SMS provider для входа.
- Сохранить существующие session, rate limit, secure native bearer storage и Push device registration.
- Обновить regression tests и документацию.

## Out of Scope

- Отправка SMS-кодов.
- Удаление уже применённой PostgreSQL migration; неиспользуемые таблицы не читаются runtime.
- Admin массовая SMS-рассылка.

## Architecture / Constraints

- Backend остаётся источником истины для customer/session.
- Только phone-only UI не означает подтверждение владения номером; это lightweight identification boundary.
- Native Push permission/token flow не изменяется.

## Acceptance Criteria

- Auth modal содержит только поле номера телефона.
- Web и native вызывают только `/auth/identify`; `/auth/sms/*` не вызывается приложением.
- Backend принимает запрос только с номером и создаёт сессию с безопасным fallback-именем.
- Existing tests, lint, typecheck and build pass.

## Progress

- [x] Зафиксировать owner decision.
- [x] Обновить auth contract, Backend и Customer UI.
- [x] Выполнить verification и синхронизировать документацию.

## Discoveries

- Existing `/auth/identify` already provides the required session boundary; the extra OTP path is not needed for the requested product behavior.

## Decision Log

- Сохраняется lightweight identification без SMS verification: это прямо соответствует уточнённому UX и не создаёт платные внешние сообщения.

## Outcome

Вход на Web/iOS/Android переведён на единый `/auth/identify`: обязательным остаётся только номер телефона, имя получает безопасный fallback `Гость`, SMS-код и SMS provider для авторизации не используются. Native Push registration/preferences сохранены отдельно.

Проверки после изменения: API client 84, API 117, Customer 28, Admin 19, contracts 52 и database 25 — всего 325 package tests; full Playwright прошёл 22/22 на одном worker. Также прошли lint, typecheck, build, audit, canonical migration/probe и `git diff --check`.
