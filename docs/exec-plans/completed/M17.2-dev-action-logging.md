# M17.2 — Detailed Development Action Logging

Status: completed
Milestone: M17 Native validation
Depends on: M17.1 cloud preview, M15 native Customer

## Purpose

Сделать локальную проверку Customer наблюдаемой в реальном времени: видеть на одной временной шкале UI taps, screen lifecycle, API requests/responses/errors и duration без записи секретов.

## Scope

- Dev-only structured logger для Customer Metro console.
- Trace wrapper для Customer API clients с method/path/status/duration/requestId-safe metadata.
- Logged Pressable для accessibility label, role, disabled state и handler duration.
- Screen open/close trace для Customer surfaces.
- Existing Fastify request logs остаются источником Backend method/path/status/requestId/duration.
- Regression tests and README usage instructions.

## Out of Scope

- Production analytics, remote log storage, Sentry/DataDog and new infrastructure.
- Logging phone numbers, bearer tokens, cookies, payment bodies or personal data.
- In-app log viewer.

## Architecture / Constraints

- Logging is disabled unless `EXPO_PUBLIC_DEBUG_LOGS=1` and is always disabled in production.
- Logs contain only allowlisted metadata; arbitrary request/response bodies are never serialized.
- No change to business logic or API contracts.
- Expo Go remains the local development target; release builds do not expose debug logs.

## Acceptance Criteria

- Each Customer press emits a timestamped event with label and disabled/role metadata.
- Each Customer API call emits start and finish/error with elapsed milliseconds and safe path/status.
- Screen lifecycle is visible in Metro terminal.
- Existing tests/build/lint/typecheck pass.

## Discoveries

- Fastify already emits useful incoming/completed request logs; the missing observability layer is Customer UI/client tracing.

## Decision Log

- Logs stay local in Metro/API terminals to avoid introducing a remote logging service for a small first-release workload.
- Redaction is enforced by allowlisted fields rather than logging arbitrary payloads.

## Outcome

Dev tracing реализован в Customer через local Metro console: `ui.press.*`, `screen.*` и `api.request.*` содержат timestamp, safe label/path, HTTP method/status/requestId и durationMs. Backend Fastify error logs дополнены event/requestId/method/path/status/errorCode без body/PII. Включение выполняется только переменной `EXPO_PUBLIC_DEBUG_LOGS=1`; production runtime всегда отключает Customer debug logger.

Verification: Customer typecheck/lint и 29 Customer tests passed; full project verification до instrumentation уже прошла, а `git diff --check` проверен после изменений. Логи читаются в живом Metro terminal и API terminal; remote log infrastructure не добавлялась.
