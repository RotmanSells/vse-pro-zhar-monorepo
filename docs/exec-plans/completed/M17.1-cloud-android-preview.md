# M17.1 — Cloud Android Preview Updates

Status: completed
Milestone: M17 Native validation
Depends on: M15 native Push, Expo Customer target

## Purpose

Подготовить облачный цикл Android preview: один APK устанавливается на устройство, а последующие JS/UI-изменения публикуются из GitHub Actions через EAS Update без постоянно запущенного ПК.

## Current State

- Customer — Expo SDK 57 с native iOS/Android targets.
- Native Push уже подключён через `expo-notifications`.
- EAS Update и `expo-updates` пока не настроены.
- Backend пока запускается локально; для реального удалённого тестирования нужен публичный API URL.

## Scope

- Подключить `expo-updates` и runtime version policy.
- Добавить Android preview APK profile с channel `preview`.
- Добавить ручной GitHub Actions workflow для запуска облачной APK-сборки.
- Добавить GitHub Actions workflow для публикации Android preview update из ветки `preview`.
- Использовать EAS environment variables для `EXPO_PUBLIC_API_URL` и `EXPO_PUBLIC_EAS_PROJECT_ID`.
- Документировать одноразовую настройку Expo project/token и поведение native vs JS изменений.

## Out of Scope

- Реальный EAS build/update без owner Expo account и GitHub secret.
- Deployment Backend и PostgreSQL в облако.
- TestFlight/Google Play submission.
- Hot Updater и отдельная self-hosted OTA infrastructure.

## Architecture / Constraints

- Build и update выполняются в Expo/GitHub cloud, не на пользовательском ПК.
- OTA меняет только совместимый JS/style/assets слой; native dependencies/configuration требуют нового APK.
- Preview channel не смешивается с production channel.
- Public API URL можно передавать в клиентский bundle; secrets в Customer bundle запрещены.

## Implementation Requirements

- Dynamic Expo app config derives `updates.url` and Push project id from `EXPO_PUBLIC_EAS_PROJECT_ID`; no fake project id is committed.
- `runtimeVersion.policy = appVersion` prevents incompatible native updates.
- GitHub Action runs only for `preview` pushes or manual dispatch and uses `EXPO_TOKEN` secret.
- EAS preview environment must provide `EXPO_PUBLIC_API_URL` and `EXPO_PUBLIC_EAS_PROJECT_ID`.

## Acceptance Criteria

- `expo config --type public --json` shows `expo-updates`, runtime policy, iOS/Android platforms and dynamic EAS URL when project id is provided.
- `eas.json` defines an Android APK preview build and `preview` channel.
- GitHub Action contains no credentials in repository and publishes only Android preview updates.
- Local project build/typecheck/lint/tests remain green.
- Documentation clearly states the first APK/native changes still require cloud rebuild.

## Discoveries

- EAS Update публикует только совместимые с native runtime JS updates; при изменении native-модулей нужен новый build.
- Hot Updater также поддерживает Expo, но добавляет self-hosted storage/database и `prebuild`, что не нужно для текущего preview-цикла.

## Decision Log

- Выбран EAS Update + GitHub Actions: это минимальный cloud workflow для существующего Expo проекта без постоянного локального процесса.
- Публикация ограничена веткой `preview`; production channel не будет обновляться случайным push.

## Outcome

Cloud preview configuration implemented. Customer now uses `expo-updates` with `runtimeVersion.policy = appVersion`, dynamic EAS URL/project id from `EXPO_PUBLIC_EAS_PROJECT_ID`, `eas.json` Android APK profile on `preview` channel, automatic GitHub Action OTA publish on `preview` pushes and a manual cloud APK build workflow.

Verification passed: Expo config with and without project id, YAML parse, lint, typecheck, 325 package tests, build, audit, canonical migration/probe and `git diff --check`. Full Playwright remains 22/22 from the same Customer/Expo codebase before cloud-only workflow files; no cloud build/update was started because this workspace has no owner EAS project id, GitHub `EXPO_TOKEN` or public deployed Backend URL.
