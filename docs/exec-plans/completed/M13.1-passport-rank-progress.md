# M13.1 — Passport: XP progress и следующий ранг

Status: completed
Milestone: M13
Depends on: M13 Loyalty

## Purpose

Довести текущую Customer loyalty-поверхность до базового визуального и функционального уровня Passport из prototype:

- показать текущий XP;
- показать progress до следующего rank;
- показать следующий rank и оставшееся количество XP;
- корректно обработать максимальный rank;
- сохранить Backend + PostgreSQL как единственный источник истины.

Это отдельная задача после M13. Она не включает quests, roulette, rewards shop или redemption.

## Current State

- M13 уже реализует server-owned XP, угольки, rank, append-only ledger и Customer/Admin loyalty reads.
- `GET /loyalty` возвращает `xp`, `coalBalance`, текущий `rank`, `version` и `updatedAt`.
- Backend хранит утверждённую rank ladder в `apps/api/src/loyalty/service.ts` и уже вычисляет rank по XP.
- `LoyaltyRank` содержит `thresholdXp`, но Customer не получает server-computed `nextRank` или progress projection.
- Customer `LoyaltyScreen` показывает текущий rank, XP, угольки и историю, но не показывает XP bar и следующий rank.
- В UI запрещено дублировать rank thresholds и формулу прогресса вручную.

## Scope

### Backend

- Добавить в server-owned loyalty summary derived projection:
  - `currentXp` или использовать существующий `xp` без дублирования;
  - `currentRank`;
  - `nextRank: RankSummary | null`;
  - `xpIntoCurrentRank`;
  - `xpToNextRank`;
  - bounded `progressPercent`;
  - `isMaxRank`.
- Рассчитывать projection внутри `LoyaltyService` из единой server-side rank ladder.
- Для максимального rank возвращать `nextRank = null`, `xpToNextRank = 0`, `progressPercent = 100`, `isMaxRank = true`.
- Не менять earn formula, rank thresholds, ledger, payment boundary или order lifecycle.

### Shared contracts/API client

- Расширить strict loyalty contracts для rank-progress projection.
- Runtime-валидировать новые поля в `LoyaltySummaryResponseSchema`.
- Сохранить существующий `LoyaltyClient.getSummary()` и lifecycle controller; не добавлять отдельный клиентский источник rank state.

### Customer UI

- Перенести текущую summary-card в визуальную форму Passport prototype:
  - rank name/icon;
  - XP value;
  - progress bar;
  - текст «До ранга … осталось … XP»;
  - состояние максимального rank.
- Отображать только подтверждённые значения из Backend.
- Добавить loading, unavailable, error и max-rank states без optimistic XP.
- Не добавлять quests, rewards, roulette, fake benefits или ручное изменение XP.

### Admin

- В рамках этой задачи Admin UI не расширять.
- Если Admin получает расширенный summary contract, использовать поля только для safe read presentation; отдельные Admin mutations запрещены.

## Out of Scope

- Quests и quest progress.
- Roulette/wheel.
- Reward catalog, reward definitions UI и redemption.
- Campaigns, multipliers, referrals, birthday rules.
- Изменение XP/rank вручную.
- Новая PostgreSQL migration или отдельная database.
- Хардкод rank thresholds/progress formula в Customer/Admin.
- Перенос prototype-only business logic.

## Architecture / Constraints

- Backend + PostgreSQL остаются authoritative source для XP/rank/loyalty state.
- Contracts владеют формой данных и runtime validation.
- LoyaltyService владеет rank ladder, threshold selection и progress calculation.
- Routes владеют auth/error mapping.
- API client/controller владеют transport/lifecycle.
- Customer UI владеет только presentation.
- Расчёты используют integer XP; floating-point money logic не вводится.
- Progress вычисляется только на Backend и ограничивается диапазоном `0..100`.
- Одна canonical database: `vse_pro_zhar_dev`; миграции для derived projection не нужны.

## Implementation Requirements

### Lego boundaries

1. `packages/contracts`: добавить strict `LoyaltyRankProgress` schema/type.
2. `apps/api/src/loyalty/service.ts`: добавить server-side projection из общей `LOYALTY_RANKS`.
3. `apps/api/src/loyalty/route.ts`: вернуть projection через существующий `GET /loyalty`.
4. `packages/api-client`: runtime validation существующего summary response.
5. `apps/customer/src/components/loyalty-screen.tsx`: отрисовать Passport rank card/progress states.
6. Tests на каждом затронутом lego boundary.

### Expected projection rules

- `xpIntoCurrentRank = xp - currentRank.thresholdXp`.
- Для не-максимального rank:
  - `xpToNextRank = nextRank.thresholdXp - xp`;
  - `progressPercent = floor(100 * xpIntoCurrentRank / (nextRank.thresholdXp - currentRank.thresholdXp))`, bounded to `0..99` before max rank.
- Для максимального rank:
  - `nextRank = null`;
  - `xpToNextRank = 0`;
  - `progressPercent = 100`;
  - `isMaxRank = true`.
- Backend повторно проверяет rank/account consistency before returning confirmed summary; inconsistency remains unavailable.

- Browser check confirms Passport card has no horizontal overflow at 320, 375, 768 and 1024 px.

## Acceptance Criteria

- Customer sees a Backend-confirmed XP progress bar and next rank.
- Progress uses the approved Backend rank ladder; no thresholds are duplicated in UI code.
- Max rank is rendered as completed without a fake next rank.
- Unknown/unavailable loyalty state never renders a successful progress result.
- Existing XP/coal earn, ledger, payment and order behavior remains unchanged.
- No quests, roulette, rewards or new business logic are introduced.
- Canonical database remains `vse_pro_zhar_dev`; no new database or migration is created.

## Discoveries

- Текущий `LoyaltyRank` уже содержит `thresholdXp`, но текущий Customer summary не содержит следующего rank или server-computed progress.
- В Backend уже есть единая rank ladder и `rankForXp`, поэтому отдельная ladder в UI не нужна и запрещена.
- Derived rank progress не требует отдельной persistence или migration.
- Существующий `GET /loyalty` уже валидирует response на route boundary, поэтому для нового projection достаточно расширить shared schema и сохранить текущий API client/controller lifecycle.
- Для Customer Web и native-compatible UI вместо нового icon dependency использован небольшой code-native rank mark; rank code влияет только на его presentation color.

## Decision Log

- Rank progress остаётся Backend-derived projection в существующем `GET /loyalty`, а не отдельным endpoint.
- Projection развёрнут в текущем `summary`: `xp` и `rank` остаются единственными current XP/current rank полями, а новые значения добавлены без дублирования.
- Contract дополнительно запрещает противоречивые max/non-max комбинации, чтобы malformed state не стал успешным UI state.
- Customer показывает только подтверждённую projection; unknown/unavailable состояния остаются safe/unavailable.
- M13.1 не расширяет rewards/redemption и не переходит к M14 Wheel + Quests.

## Outcome

M13.1 реализована в заявленном scope.

- Shared contracts теперь валидируют плоскую rank-progress projection в `GET /loyalty`: `nextRank`, `xpIntoCurrentRank`, `xpToNextRank`, bounded `progressPercent` и `isMaxRank`. Для max rank contract требует `nextRank = null`, `xpToNextRank = 0` и `progressPercent = 100`.
- `LoyaltyService` рассчитывает projection только из `LOYALTY_RANKS`, повторно проверяет rank/account consistency и возвращает безопасный unavailable при расхождении. Earn formula, ledger, order/payment lifecycle и PostgreSQL schema не изменялись.
- Customer Passport показывает подтверждённый rank mark, XP, угольки, progress bar, следующий rank/остаток XP и max-rank state. Loading, unavailable, error и отсутствие client input покрыты тестами; Admin UI не расширялся.
- Добавлены contract, Backend, API-client runtime-validation, Customer component и E2E assertions. `pnpm lint`, `pnpm typecheck`, `DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5432/vse_pro_zhar_dev pnpm test` (216 тестов), `pnpm build` и `git diff --check` прошли.
- Точечная headless browser-проверка штатной локальной пары Customer `8082` → API `3001` прошла: Passport/progress видимы, `input` отсутствует, `scrollWidth` не превышает viewport на 320, 375, 768 и 1024 px. Playwright через repository `webServer` на этом host не использован для итогового статуса из-за занятого 8082 и игнорируемого `.env.local`, подставляющего API port 3001; первая попытка также запустила весь suite и упала в unrelated `admin-orders`.
