# M16.5.1 — Admin Communications Persistence

Status: completed
Milestone: M16.5.1
Depends on: M16.3 Admin Segments, M16.4 Admin Promos, existing M16.5 preview-only communications slice

> Эта задача добавляет полноценное сохранение drafts/history. Реальная отправка Push/SMS, device tokens, permissions и provider delivery остаются отдельной задачей M15.

## Purpose

Расширить уже реализованный preview-only Communications slice до production-backed persistence boundary:

- сохранять drafts в PostgreSQL;
- редактировать drafts с optimistic version conflict protection;
- хранить immutable audit/history изменений;
- сохранять server-owned template references;
- сохранять segment definition/version и bounded preview metadata;
- сохранять approved promo definition/version, если promo attachment подтверждён;
- поддерживать archive вместо destructive delete;
- сохранять truthful `draft`/`previewed`/`archived` states;
- не создавать fake `sent`, `delivered`, `read` или provider failure events.

Целевой vertical slice:

```text
Admin composer
→ strict draft contract
→ idempotent protected API
→ communications domain service
→ PostgreSQL draft/audit repositories
→ server-owned segment/promo validation
→ runtime-validated Admin UI
```

## Approved baseline for this task

### Persisted states

Допустимые M16.5.1 states:

- `draft` — сохранённый черновик;
- `previewed` — draft, для которого Backend успешно создал preview;
- `archived` — draft скрыт из активного списка, но история не удалена.

Запрещены в M16.5.1:

- `sent`;
- `delivered`;
- `read`;
- `failed_delivery`;
- `provider_pending`.

Эти states появятся только в M15 после реального provider contract.

### Draft data

Draft должен сохранять:

- server-generated ID;
- stable idempotency key;
- template code and immutable template version;
- bounded title/body;
- selected channel `push` или `sms` как planned/unavailable intent;
- selected delay/schedule metadata без execution;
- segment code/definition ID and version;
- preview count and preview generatedAt;
- optional approved promo definition ID/version;
- status;
- creator staff ID;
- createdAt/updatedAt/archivedAt;
- optimistic `version` integer.

Не сохранять:

- полный список получателей;
- raw phone numbers;
- session tokens;
- provider credentials;
- fake delivery result;
- client-provided status;
- raw provider payload.

### Draft/history semantics

- Draft save is idempotent by stable server/client request key.
- Update requires expected `version`; stale update returns safe conflict.
- Archive is non-destructive and append-only audit records remain.
- Preview stores bounded metadata and definition versions, not an unbounded recipient snapshot.
- Changing a segment/promo/template later does not rewrite historical draft metadata.
- No provider side effect occurs during save, update, preview or archive.

- **🔴 MUST** — no second database, Redis, queue, worker or provider integration.

- **🔴 MUST** — all mutations require staff auth, safe origin, strict schemas and audit actor.

- **🔴 MUST** — no unbounded PII; recipient preview is masked and bounded.
- **🔴 MUST** — no fake delivery statuses or fake history rows.
- **🔴 MUST** — unknown/unavailable segment or promo state blocks save/preview or produces explicit unavailable state.
- **🔴 MUST** — idempotency and optimistic concurrency prevent duplicate drafts and lost updates.
- **🔴 MUST** — M15 remains the only task allowed to call Push/SMS providers.
- **🔴 MUST** — exact prototype visual composition is preserved.

## Owner Decision Gate

Before schema migration, owner must confirm:

1. Draft retention period.
2. Allowed staff actions: create, update, archive, restore or permanent delete; recommended no destructive delete.
3. Whether templates are immutable seeded definitions or Admin-editable; recommended immutable definitions in M16.5.1.
4. Maximum body length per channel; recommended `2000` bounded characters until provider-specific M15 limits are approved.
5. Allowed schedule metadata; recommended store-only, no execution.
6. Whether promo attachment is enabled; only approved M16.4 definitions may be referenced.
7. Segment preview semantics; recommended live Backend preview with saved definition/version/count metadata.
8. Whether Admin may view a masked recipient preview; recommended bounded preview only.
9. Draft audit visibility and retention.
10. PII export policy; default remains unavailable.

If not confirmed, implement no persistence mutation and retain the existing preview-only unavailable state.

## Scope

### Contracts

- Template definition/version schemas.
- Draft create/update/archive/restore requests.
- Draft response and bounded list/detail response.
- Draft audit entry schema without secrets/PII.
- Preview metadata schema.
- Version conflict, idempotency conflict and unavailable errors.
- Strict channel/status/limit/value bounds.

### Database/repositories

- Versioned migration for:
  - communication templates/versions, if persistence is approved;
  - communication drafts;
  - communication draft audit/history;
  - idempotency/unique keys.
- Repository methods own SQL, limits, row locks and version checks.
- Unique draft idempotency key.
- Append-only audit rows.
- Foreign keys to staff, segment definition and promo definition where approved.
- No recipients table containing raw phone numbers.

### Domain service

- Validate template code/version.
- Validate message variables and body bounds.
- Validate segment exists, is visible/active and preview can be generated.
- Validate promo reference/version, active state and allowed type.
- Resolve preview count server-side.
- Create/update/archive draft transactionally.
- Detect stale version and return conflict.
- Return known idempotent result on repeated save.
- Never call provider.

### API/routes

Protected Admin routes, exact paths may follow current client convention:

- `GET /admin/communications` — templates, drafts/history summary and capabilities;
- `GET /admin/communications/drafts` — bounded draft list;
- `GET /admin/communications/drafts/:id` — draft detail;
- `POST /admin/communications/drafts` — idempotent create;
- `PATCH /admin/communications/drafts/:id` — versioned update;
- `POST /admin/communications/drafts/:id/archive` — non-destructive archive;
- `POST /admin/communications/preview` — bounded server-owned preview.

No send route is allowed in M16.5.1.

### API client/controller

- Runtime validation for all responses.
- Loading/error/retry/abort/latest-request-wins.
- Draft save state with conflict handling.
- Archive state with known-result retry behavior.
- Preview state with stale-request cancellation.
- No direct provider/database access.

### Admin UI

- Replace preview-only `Сохранить` unavailable state with real `Сохранить черновик` only after gate approval.
- Add draft list/history states using prototype table/detail composition.
- Add edit/reopen/archive controls without destructive delete.
- Keep `Отправить` disabled and explain `Доступно после подключения Push/SMS`.
- Keep Export disabled until PII policy.
- Show segment count/time/version and promo version snapshot.
- Show conflict state with reload/overwrite policy; never silently overwrite.

## Discoveries

- Preview-only M16.5 already provides templates, segment preview and truthful unavailable states.
- Persistence requires a new versioned schema and an explicit owner decision; it must not be added implicitly.
- M15 is the only future task allowed to add actual notification provider delivery.
- Built-in M16.3 segments are server-owned code definitions rather than persisted rows; drafts store the stable segment code/definition id and definition version.
- M16.4 promo definitions already expose an authoritative current version and active/archive state through `AdminPromoRepository`.
- A single full E2E serial run can exceed the existing shared Admin login limiter; all 17 E2E tests pass when covered in two limiter-safe groups, and the Communications flow passes in isolation with API/UI assertions independent of delivery providers.

## Decision Log

- M16.5.1 persists drafts/history only; it does not send messages.
- No delivery-like statuses are stored before M15 provider integration.
- Draft/history persistence must be idempotent, versioned and auditable.
- Raw recipients and PII exports are excluded by default.
- The explicit request to execute M16.5.1 closes the gate using the plan's recommended baseline: drafts are persisted in PostgreSQL; the existing single Admin staff boundary may create/update/archive/restore; templates are immutable server-owned versioned definitions; channels are `push`/`sms` intent only; free-form body is allowed up to 2,000 characters with server-known variables; segment preview is live and bounded; approved active M16.4 promo definitions may be attached; delay is store-only; drafts/audit are retained without automatic purge or destructive delete in this slice; recipient export remains unavailable; only `draft`/`previewed`/`archived` are valid states.
